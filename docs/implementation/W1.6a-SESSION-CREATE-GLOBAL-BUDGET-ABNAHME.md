# W1.6a-Abnahme: Globales Session-Create-Budget

**Stand:** 2026-07-24  
**Owner:** Backend / Security  
**Ticket:** PR-Slice W1.6a  
**Abhängigkeiten:** W1.3 (atomares Public-Create-Lua), W1.4 (vertrauenswürdige Client-IP)  
**Rollback:** Code-Revert oder Globalbudget kontrolliert erhöhen; alte
Sliding-Window-Keys verfallen automatisch

## Schutzmodell

- `session.create` bucht pro festem Stundenfenster ein globales und ein grobes
  Shared-NAT-IP-Budget atomar in Redis.
- Code-Defaults: 10 Erstellungen pro IP und 120 global. Bei
  `NODE_ENV=production` fällt das neue Globalbudget rollout-sicher auf 2400
  zurück, wenn eine bestehende persistente `.env.production` die neue Variable
  noch nicht enthält. Das Produktionsprofil verwendet bewusst großzügige 480
  pro Shared-NAT-IP und 2400 global.
- Das globale Budget wird zuerst geprüft. Ist es erschöpft, entstehen keine
  weiteren angreiferkontrollierten IP-Keys.
- Redis-Ausfall bleibt fail-closed: Session-Erstellung ist eine teure
  Host-Funktion und benötigt Redis ohnehin für das Host-Token.
- Der bestehende Localhost-Bypass gilt nur in Nicht-Produktionsumgebungen oder
  bei explizitem Override.
- Ablehnungen liefern `TOO_MANY_REQUESTS` mit einem validierten, positiven
  `retryAfterSeconds` in `shape.data`. Andere interne `cause`-Daten werden nicht
  über die tRPC-Transportgrenze serialisiert; die Fehlermeldung enthält keinen
  hardcodierten Grenzwert.

Join, Vote, Q&A, Blitzlicht-Votes und WebSockets sind von diesem Slice
unberührt. Insbesondere entsteht kein neues Teilnehmer-IP-Limit.

## Abnahmekriterien

- [x] Verteilte Session-Create-Wellen werden durch ein globales Budget begrenzt.
- [x] Global- und IP-Zähler werden in einem Lua-Aufruf nur gemeinsam erhöht.
- [x] Nach erschöpftem Globalbudget wird für eine neue IP kein Key angelegt.
- [x] Das Produktionsprofil behält ein Shared-NAT-taugliches IP-Budget.
- [x] Bestehende Produktions-Env-Dateien ohne die neue Variable behalten
      rollout-sicher 2400 globale Creates/h.
- [x] Erfolgreiche Creates und `sessionCreate`-429 bleiben über
      `health.securityStats` beobachtbar.
- [x] Der echte HTTP/tRPC-Client erhält bei einem `session.create`-429 die
      positive Wartezeit; die lokalisierte UI verwendet dieses explizite Feld.
- [x] Env-Beispiele, Security-Übersicht und Monitoring-Runbook dokumentieren
      Schutzwirkung und Betriebswerte.

bei einem Globalbudget von 5. Genau fünf werden zugelassen; anschließend bleibt
ein weiterer rotierter IP-Key aus.
