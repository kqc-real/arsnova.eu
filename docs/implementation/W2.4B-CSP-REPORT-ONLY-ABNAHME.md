# W2.4b – CSP Report-Only: Abnahme

**Stand:** 2026-07-25

**Scope:** Backend-ausgelieferte Angular-Anwendung; kein Enforcement

## Ergebnis

W2.4b ergänzt ausschließlich den Header
`Content-Security-Policy-Report-Only`. Der rollout-sichere Standard
`CSP_REPORT_ONLY_ENABLED=false` liefert keinen CSP-Header. Nur der exakte Wert
`true` aktiviert die feste, nicht per Env manipulierbare Policy. Rollback
erfolgt durch Zurücksetzen des Flags und Neustart des App-Containers.

Der Header wird genau einmal und erst beim Schreiben einer erfolgreichen
GET-/HEAD-Antwort mit `Content-Type: text/html` gesetzt. Der W2.4a-Endpunkt
`/csp-report` liegt vor der Middleware. `/trpc`, der Report-Endpunkt,
JS-/CSS-/JSON-/Service-Worker-Assets und 204-Antworten erhalten weder
Report-Only noch Enforcement. HTML wird unabhängig vom Flag mit `no-store`
ausgeliefert; bedingte Dokumentnavigationen werden vor Static/Fallback von
alten ETags entkoppelt. Dadurch können 304-Antworten weder einen früher
fehlenden noch einen früher gesetzten CSP-Header konservieren. Nginx ist
ausdrücklich nicht Header-Eigentümer.

## Policy und Build-Evidenz

Die initiale Beobachtungspolicy enthält:

- `default-src 'self'`, `base-uri 'self'`, `object-src 'none'`,
  `form-action 'self'`, `frame-ancestors 'self'`;
- `script-src 'self' 'unsafe-inline' 'unsafe-eval'` und
  `script-src-elem 'self' 'unsafe-inline'`;
- `script-src-attr 'unsafe-inline'`;
- `style-src 'self' 'unsafe-inline'`;
- `img-src 'self' data: blob: https:` und `font-src 'self' data:`;
- `connect-src 'self' wss:`;
- `worker-src 'self' blob:`, `manifest-src 'self'`;
- `frame-src 'self' blob:` und `media-src 'self' blob:`;
- `report-uri /csp-report`.

`apps/frontend/src/index.html` enthält zwei frühe Inline-Scripts (Theme/Preset
und Feedback-Shell) sowie Inline-Critical-CSS. Angular Material und KaTeX
erzeugen beziehungsweise benötigen ebenfalls Inline-Styles. Der lokalisierte
Post-Build erzeugt für den asynchronen Font-Preload einen Inline-`onload`-
Handler. Der Playwright-Smoke hat außerdem reproduzierbare `eval`-Violations
aus dem Home-Lazy-Chunk gezeigt; instrumentierte Stacks belegen Zod 4 als
Quelle (`Function`-kompilierte Validatoren). Deshalb sind `unsafe-inline` für
Script-Elemente, Attribute und Styles sowie `unsafe-eval` in dieser reinen
Beobachtungspolicy evidenzbasiert enthalten. Es gibt weiterhin keine
pauschale `https:`-Scriptquelle.

Markdown akzeptiert kontrollierte HTTPS-, `blob:`- und ausgewählte
`data:image/*`-Bildquellen. Downloads und Exporte verwenden Blob-URLs.
Service-Worker und Manifest sind same-origin; tRPC-HTTP ist same-origin,
tRPC-/Yjs-Produktion verwendet `wss:`. Es wurden keine produktiven
Cross-Origin-Scripts nachgewiesen; pauschales `https:` oder `unsafe-eval` ist
daher nicht in `script-src`.

## Tests

Fokussiert:

```bash
npm test -w @arsnova/backend -- --run src/lib/cspReportOnly.test.ts
npm run typecheck -w @arsnova/backend
npx eslint apps/backend/src/lib/cspReportOnly.ts \
  apps/backend/src/lib/cspReportOnly.test.ts apps/backend/src/index.ts
```

Der Test deckt Policy-Direktiven, CR/LF-Freiheit, exakte Flag-Semantik,
lokalisierte HTML-Routen, genau einen Header, fehlendes Enforcement sowie den
negativen Scope für tRPC, `/csp-report`, JS, CSS, JSON und 204 ab.

Produktionsbuild und statischer Header-Smoke:

```bash
npm run build:localize -w @arsnova/frontend
CSP_REPORT_ONLY_ENABLED=true npm run start:prod
npm run verify:csp-report-only
npm run verify:csp-browser
```

Der Smoke ermittelt die gehashten JS-/CSS-Dateien aus dem gebauten
`/de/`-Dokument und prüft zusätzlich Manifest, Service Worker, tRPC und
`/csp-report`. Der Playwright-Smoke prüft mehrere i18n-Routen, Browserfehler,
den aktiven lokalisierten Service Worker und aktuelle Policy-Violations. Die
bestehenden A11y- und Lighthouse-Smokes bleiben unverändert relevant.

Lokaler Stand dieses Slices:

- Produktions-/Localize-Build: grün (bekannte Bundle-Budget-Warnung);
- statischer Header-Smoke aktiviert und deaktiviert: grün;
- Playwright-CSP-Smoke: drei i18n-Routen, aktiver lokalisierter Service Worker,
  keine Browserfehler, keine verbleibende Policy-Violation;
- axe: 13 Zustände ohne WCAG-Verstoß; `color-contrast` jeweils als bestehende
  manuelle `incomplete`-Prüfung;
- Yjs-Quiz-Sync-Smoke: grün;
- Unified-Session-Smoke lokal nicht vollständig ausführbar: `quiz.upload`
  scheiterte an aus dem Host nicht erreichbarem PostgreSQL/Redis
  (`ECONNREFUSED` / `Connection is closed`), nicht an CSP. Die laufenden
  Prod-Compose-Dienste veröffentlichen ihre Ports bewusst nicht. Der
  vollständige CI-Smoke mit erreichbaren Service-Containern bleibt Pflicht.

## Rollout und Monitoring

1. W2.4a-Ingest mit deaktiviertem Flag deployen.
2. `POST /csp-report` auf 204 ohne CSP-Header smoken.
3. `CSP_REPORT_ONLY_ENABLED=true` setzen und App neu starten.
4. HTML-/API-/Asset-/Report-Scope prüfen.
5. 24–72 Stunden die admin-geschützten aggregierten CSP-Signale beobachten.
6. Erst danach in einem separaten Review über Policy-Änderungen oder späteres
   Enforcement entscheiden.

Legitime Violations werden gegen Route, Browser und aktuellen Build
reproduziert. Die Policy wird nicht nur zum Absenken der Reportzahl gelockert.
Bei Report-Sturm oder Kernflow-Regressionsverdacht wird das Flag auf `false`
gesetzt; der W2.4a-Ingest bleibt verfügbar.

## Security-Preflight

- Header-Scope basiert auf tatsächlichem Response-Content-Type, nicht `Accept`.
- HTML ist flag-unabhängig `no-store`; alte bedingte Dokumentrequests werden
  vollständig beantwortet, sodass Aktivierung und Rollback sofort greifen.
- `/csp-report` kann keinen Report-Only-Header erhalten.
- Express setzt maximal einen Header; Nginx setzt keinen CSP-Header.
- Policy und Report-Pfad sind statisch, daher kein Env-/Header-Injection-Pfad.
- i18n-SPA-Fallbacks sind HTML und erhalten die Policy.
- API, statische Assets, 204 und nicht erfolgreiche Antworten bleiben frei.
- Angular-Inline-Scripts, Material/KaTeX-Styles, Worker, Manifest, WSS,
  Markdown-Bilder und Blob-Downloads wurden explizit berücksichtigt.
- Flag-Default und Produktionsbeispiel sind `false`; Rollback ist ohne
  Datenbank-, Redis- oder Nginx-Änderung möglich.
- Der lokale Prod-Starter respektiert explizite Prozessvariablen vor `.env`;
  dokumentierte `CSP_REPORT_ONLY_ENABLED=true`-Smokes überschreiben den
  Vorlagenstandard tatsächlich.

## Out of scope und Restrisiken

- Kein `Content-Security-Policy`-Enforcement, keine Nonces oder Hashes.
- Keine CORS-Änderung (W2.5).
- Landing/Astro und GitHub Pages werden nicht vom Backend ausgeliefert.
- Report-Only verhindert keinen Angriff. `unsafe-inline` und `unsafe-eval`
  bleiben bewusst belegte Beobachtungszugeständnisse. Vor Enforcement müssen
  Font-Preload-Handler und Zod-JIT strukturell ersetzt sowie Inline-Scripts über
  Nonces/Hashes abgesichert werden.
- Lokale Smokes können reale Browser-/Extension- und produktive Proxy-
  Unterschiede nicht vollständig abbilden; deshalb ist das 24–72-h-Fenster
  verpflichtend.
