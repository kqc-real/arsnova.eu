# W3.4 — Yjs Share-Tokens + manuelle Rotation (Abnahme)

**Stand:** 2026-07-26  
**Status:** umgesetzt (erster Slice B)  
**ADR:** [0033](../architecture/decisions/0033-harden-yjs-relay-and-plan-rotatable-share-tokens.md)

## Verhalten

| Aspekt    | Umsetzung                                                                                                     |
| --------- | ------------------------------------------------------------------------------------------------------------- |
| Token     | `v1.<roomUuid>.<generation>.<hmac>` per HMAC-SHA256 (`YJS_SHARE_TOKEN_SECRET` oder abgeleitetes `JWT_SECRET`) |
| Transport | WebSocket-Query `?s=<token>`; App-Sync-Link `/quiz/sync/<uuid>?s=<token>`                                     |
| Metadaten | Redis `yjs:share:v1:<roomUuid>` → `generation`, `rotationCapabilityHash`                                      |
| Rotation  | UI „Sync-Link ungültig machen“ (nur Ursprungsgerät mit Capability)                                            |
| Legacy    | UUID-only Connect bis `YJS_SHARE_LEGACY_UUID_CUTOFF_AT` (Default `2026-10-01T00:00:00.000Z`)                  |
| Logging   | Keine Tokens/Capabilities; Upgrade-Reject nur mit `reason`                                                    |

## Abnahme

- [ ] Origin: Sync-Seite registriert Share, kopierter Link enthält `?s=`
- [ ] Zweites Gerät: Link-Import verbindet; kein „ungültig machen“
- [ ] Origin: ungültig machen → alter Link/WS-Upgrade 400; neuer Link verbindet
- [ ] Offline nach Widerruf: lokale Quizze bleiben; Sync erst mit neuem Link
- [ ] Bis Cutoff: UUID-only weiterhin möglich; danach abgelehnt
- [ ] Nginx/Access-Logs: Query `s` redigieren (betrieblich prüfen)

## Residualrisiko

- Bis Legacy-Cutoff bleibt Raum-UUID voller Bearer-Zugriff.
- Verlorene Rotations-Capability: kein Widerruf mehr möglich → neuer lokaler Raum / Copy-out.
- Signing-Key-Rotation (Überlappung alter Signaturen) ist bewusst nicht in diesem Slice.
