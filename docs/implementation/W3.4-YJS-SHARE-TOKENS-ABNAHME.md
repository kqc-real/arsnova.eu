# W3.4 — Yjs Share-Tokens + manuelle Rotation (Abnahme)

**Stand:** 2026-07-26  
**Status:** umgesetzt (erster Slice B)  
**ADR:** [0033](../architecture/decisions/0033-harden-yjs-relay-and-plan-rotatable-share-tokens.md)

## Verhalten

| Aspekt    | Umsetzung                                                                                                                                  |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Token     | `v1.<roomUuid>.<generation>.<hmac>` per HMAC-SHA256 (`YJS_SHARE_TOKEN_SECRET` oder abgeleitetes `JWT_SECRET`, ≥32 Bytes; Prod fail-closed) |
| Transport | WebSocket-Query `?s=<token>`; App-Sync-Link `/quiz/sync/<uuid>#s=<token>` (kein HTTP-/Nginx-Transport); Browser entfernt `s` nach Import   |
| Metadaten | Redis `yjs:share:v1:<roomUuid>` (TTL 730d) → `generation`, `rotationCapabilityHash`; atomar per Lua                                        |
| Origin    | Absichern erzeugt immer eine serverseitig gewählte neue Raum-UUID; alte/übergebene UUIDs können nicht registriert werden                   |
| Rekey     | Neue lokale Bibliothek automatisch; bestehender Legacy-Origin explizit über „Neuen abgesicherten Sync-Link erstellen“                      |
| Limits    | Create/Rotate getrennt rate-limitiert (IP + global); Hard-Cap 100k aktive Share-Keys über TTL-synchronen Redis-ZSET-Ablaufindex            |
| Rotation  | UI „Sync-Link ungültig machen“ (nur Ursprungsgerät mit Capability); Copy erst nach Token                                                   |
| Laufzeit  | Relay hält die Generation je Verbindung; Rotation terminiert ältere/Legacy-Verbindungen; zweite Auth vor Attach schließt das Race          |
| Legacy    | UUID-only Connect bis `YJS_SHARE_LEGACY_UUID_CUTOFF_AT` (Default `2026-10-01T00:00:00.000Z`); tokenisierte Räume verlangen immer `?s=`     |
| Logging   | Keine Tokens/Capabilities; Nginx `arsnova_privacy` ohne Query/Referer und kein Error-Log für den sensitiven Yjs-Pfad                       |

## Abnahme

- [ ] Neuer Origin: Backend erzeugt eine neue Raum-UUID; Kopieren erst mit Token, Link enthält `#s=`
- [ ] Bestehender Legacy-Origin: explizite Aktion rekeyt lokale Sammlung direkt auf neuen Raum
- [ ] Fremder UUID-Link ohne `s`: keine Registrierung / kein Capability-Claim unter der alten UUID
- [ ] Zweites Gerät: Link-Import verbindet; `s` verschwindet aus der Adresszeile; kein „ungültig machen“
- [ ] Origin: ungültig machen → alter Link/WS-Upgrade 400; neuer Link verbindet
- [ ] Bereits verbundener alter Client wird bei Rotation getrennt; Updates fließen nicht zwischen alter und neuer Generation
- [ ] Rotation während laufender Upgrade-Autorisierung: alter Token wird vor dem Attach abgewiesen
- [ ] Parallele Create-Pfade teilen ein In-flight-Promise und erzeugen genau einen Serverraum
- [ ] App-Reload lädt den persistierten Token vor Aufbau des Providers
- [ ] Ersatz-Token wird generationsmonoton und erst nach erfolgreichem WS-Sync persistiert; manipulierter Token fällt auf den letzten gültigen zurück
- [ ] Rotation in einem Tab aktualisiert Token, UI und Provider der anderen Tabs
- [ ] Offline nach Widerruf: lokale Quizze bleiben; Sync erst mit neuem Link
- [ ] Bis Cutoff: UUID-only weiterhin möglich, ohne Redis-Schreibzugriff; danach abgelehnt
- [ ] Nginx: `log_format arsnova_privacy` in HTTP- und HTTPS-VHost; Access-Log ohne Query/`s`
- [ ] Nginx-Error-Log schreibt für den tokenführenden Yjs-Upgrade-Pfad keine Request-Zeile
- [ ] Nach TTL-Ablauf gibt der ZSET-Ablaufindex Hard-Cap-Kapazität wieder frei
- [ ] Produktion ohne Secret ≥32 Bytes startet nicht
- [ ] Gesetzter ungültiger Legacy-Cutoff bricht den Start ab
- [ ] Redis-7-Lua-/TTL-/ZSET-Integrationstest läuft verpflichtend im PR-CI-Job

## Tokenbasierte 500-Client-Abnahme

Lokaler Reconnect-Lauf am 2026-07-26 gegen Redis 7 und den Yjs-Relay:

```bash
CLIENTS=500 YJS_SHARE_TOKEN='<redacted>' npm run load:yjs:token-reconnect
```

- Initial: 500/500, Connect-p95 95 ms, Maximum 101 ms
- Reconnect: 500/500, Connect-p95 94 ms, Maximum 98 ms
- Schwellwert: p95 ≤ 5.000 ms
- Token und Capability werden weder im Report noch in der Konsolenausgabe ausgegeben.

## Redis-7-Integration

`RUN_REDIS_YJS_SHARE_TESTS=1 npm test -w @arsnova/backend -- --run src/lib/yjsShareToken.redis.test.ts`
führt die Lua-Skripte gegen einen echten Redis-7-Server aus. Geprüft werden
Create, capability-geprüfte Rotation, Hash-TTL, ZSET-Index und das atomare
Entfernen abgelaufener Indexeinträge. Der Lauf vom 2026-07-26 ist grün.

## Residualrisiko

- Bis Legacy-Cutoff bleibt Raum-UUID voller Bearer-Zugriff (ohne Share-Metadaten).
- Verlorene Rotations-Capability: kein Widerruf mehr möglich → Rekey / neuer lokaler Raum.
- Signing-Key-Rotation (Überlappung alter Signaturen) ist bewusst nicht in diesem Slice.
