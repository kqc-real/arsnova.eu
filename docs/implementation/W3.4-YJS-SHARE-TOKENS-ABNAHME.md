# W3.4 — Yjs Share-Tokens + manuelle Rotation (Abnahme)

**Stand:** 2026-07-26  
**Status:** umgesetzt (erster Slice B)  
**ADR:** [0033](../architecture/decisions/0033-harden-yjs-relay-and-plan-rotatable-share-tokens.md)

## Verhalten

| Aspekt    | Umsetzung                                                                                                                                  |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Token     | `v1.<roomUuid>.<generation>.<hmac>` per HMAC-SHA256 (`YJS_SHARE_TOKEN_SECRET` oder abgeleitetes `JWT_SECRET`, ≥32 Bytes; Prod fail-closed) |
| Transport | WebSocket-Query `?s=<token>`; App-Sync-Link `/quiz/sync/<uuid>?s=<token>`; Browser entfernt `s` nach Import (replaceUrl)                   |
| Metadaten | Redis `yjs:share:v1:<roomUuid>` (TTL 730d) → `generation`, `rotationCapabilityHash`; atomar per Lua                                        |
| Origin    | Nur mit lokaler Capability oder eigener lokaler Bibliothek (`secureAsOrigin`); fehlendes `?s=` allein autorisiert nicht                    |
| Rekey     | Nach UUID-only-Seen oder fremder Capability: neuer Raum + neue Capability                                                                  |
| Limits    | Register/Rotate getrennt rate-limitiiert (IP + global); Hard-Cap 100k Share-Keys                                                           |
| Rotation  | UI „Sync-Link ungültig machen“ (nur Ursprungsgerät mit Capability); Copy erst nach Token                                                   |
| Legacy    | UUID-only Connect bis `YJS_SHARE_LEGACY_UUID_CUTOFF_AT` (Default `2026-10-01T00:00:00.000Z`); tokenisierte Räume verlangen immer `?s=`     |
| Logging   | Keine Tokens/Capabilities; Nginx `arsnova_privacy` mit `$uri` ohne Query/Referer                                                           |

## Abnahme

- [ ] Origin: Sync-Seite registriert Share, Kopieren erst mit Token, Link enthält `?s=`
- [ ] Fremder UUID-Link ohne `s`: keine Origin-Registrierung / kein Capability-Claim
- [ ] Zweites Gerät: Link-Import verbindet; `s` verschwindet aus der Adresszeile; kein „ungültig machen“
- [ ] Origin: ungültig machen → alter Link/WS-Upgrade 400; neuer Link verbindet
- [ ] Offline nach Widerruf: lokale Quizze bleiben; Sync erst mit neuem Link
- [ ] Bis Cutoff: UUID-only weiterhin möglich; danach abgelehnt
- [ ] Nginx: `log_format arsnova_privacy` aktiv; Access-Log ohne Query/`s`
- [ ] Produktion ohne Secret ≥32 Bytes startet nicht

## Residualrisiko

- Bis Legacy-Cutoff bleibt Raum-UUID voller Bearer-Zugriff (ohne Share-Metadaten).
- Verlorene Rotations-Capability: kein Widerruf mehr möglich → Rekey / neuer lokaler Raum.
- Signing-Key-Rotation (Überlappung alter Signaturen) ist bewusst nicht in diesem Slice.
