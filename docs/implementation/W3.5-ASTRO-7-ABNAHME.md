# W3.5 – Astro 7: Abnahme

Stand: 2026-07-26

## Ziel

Die statische Landingpage wird von Astro 6.4 auf Astro 7.1 migriert. Damit
entfällt der von den Astro-6-Abhängigkeiten verursachte Security-Befund, ohne
Rendering, GitHub-Pages-Build oder Barrierefreiheit zu verschlechtern.

## Umsetzung

- Die ungenutzte Astro-6-Root-Deklaration entfernt und `astro` im
  Landing-Workspace auf `^7.1.3` aktualisiert; der Dependency-Graph enthält
  dadurch nur Astro 7.1.3.
- Die bereits geforderte Mindestversion Node 22.12 beibehalten und die beiden
  Projektpfade Node 22 und 24 validiert.
- `cookie` 2 als Root-Dev-Dependency fixiert. Astro 7 benötigt dessen
  ESM-Named-Exports beim Prerendering; andere Workspaces behalten ihre
  inkompatible `cookie`-0.7-Version transitiv unter Express.
- `@astrojs/check` und `npm run check -w @arsnova/landing` ergänzt.
- Den Astro-Hinweis für das absichtlich unverarbeitete JSON-LD-Skript durch
  explizites `is:inline` aufgelöst.
- Den Landing-CI-Job um `astro check` vor dem Produktions-Build erweitert.

Die Landingpage verwendet keine Content Collections, Markdown-/MDX-Pipelines,
Integrationen oder experimentellen Astro-APIs. Daher waren keine
Quellcode-Migrationen für den neuen Compiler und Markdown-Prozessor notwendig.

## Abnahme

Lokal mit Node 24.18; Check und Build zusätzlich mit Node 22.23:

- `npm run check -w @arsnova/landing`: 21 Dateien, 0 Fehler, 0 Warnungen,
  0 Hinweise.
- `npm run build -w @arsnova/landing`: 3 HTML-Seiten sowie `robots.txt` und
  `sitemap.xml` erfolgreich statisch erzeugt.
- `npm run test:a11y -w @arsnova/landing`: 3 Routen, 0 blockierende
  WCAG-Verstöße.
- HTTP-Smoke für `/`, `/impressum/`, `/datenschutz/`, `/robots.txt`,
  `/sitemap.xml`, `/favicon.svg` und `/og.png`: alle Antworten erfolgreich.
- Desktop- und Mobile-Viewport visuell geprüft; kein auffälliger
  Layout-/Whitespace-Unterschied.
- `npm audit --workspace @arsnova/landing`: 0 bekannte Schwachstellen.

## Rollout

Die Landingpage bleibt ein statischer Build. Es entstehen keine neuen
Umgebungsvariablen, Datenmigrationen oder Server-/Nginx-Anpassungen.
