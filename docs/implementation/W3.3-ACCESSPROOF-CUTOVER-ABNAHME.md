# W3.3 — accessProof-Cutover (Abnahme)

**Stand:** 2026-07-26  
**Status:** umgesetzt (Code); Cutoff-Datum per Env anpassbar

## Ziel

Content-abgeleitete Legacy-`accessProof`s (SHA-256-Hex) dürfen nach erfolgreichem
Bind (`historyScopeId`) Historien-Endpunkte nicht mehr öffnen. Die Capability ist
die Scope-UUID. Die bestehende Bind-Pipeline wird nicht neu gebaut.

## Verhalten

| Pfad                   | Vor Bind (`historyScopeId` null)     | Nach Bind                                                                                                      |
| ---------------------- | ------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| Historien-Endpunkte    | Content-Hash = Capability            | nur Scope-UUID                                                                                                 |
| `bindQuizHistoryScope` | Content-Hash bindet und liefert UUID | Legacy-Hex nur bis `QUIZ_HISTORY_LEGACY_PROOF_CUTOFF_AT` (Default `2026-09-01T00:00:00.000Z`) zum UUID-Upgrade |

Frontend (`resolveQuizHistoryAccessProof`): bei vorhandener Server-Quiz-ID wird
gebunden; bei Fehlschlag kein stiller Legacy-Fallback mehr.

## Logging

- `quiz_history_legacy_proof_accepted_for_bind` — Legacy auf gebundener Kopie vor Cutoff
- `quiz_history_legacy_proof_rejected_after_bind` — Legacy auf Historie oder nach Cutoff

## Residualrisiko

- Ungebundene Uploads: Content-Hash bleibt Claim-fähig bis zum Bind.
- Nach Cutoff: unmigrierte lokale Karten ohne UUID verlieren Historienzugriff
  (accountfrei, keine Wiederherstellung).
- Optionaler zweiter Besitznachweis bewusst nicht in diesem Slice.
